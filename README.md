# خالد الحمدان — موقع المدونة

موقع ثابت (HTML/CSS/JS فقط) بلا نظام إدارة محتوى وبلا خطوة بناء.
تضع الملفات في المستودع، فيعمل الموقع كما هو.

---

## ١) النشر على GitHub Pages

إن كان اسم المستودع `khalidreads.github.io` فسيظهر الموقع على العنوان نفسه.

**من المتصفح مباشرة:**

1. افتح المستودع في GitHub.
2. اضغط `Add file` ← `Upload files`.
3. اسحب **محتويات** مجلد `site` كلها (لا المجلد نفسه): أي `index.html` و`assets` و`posts` وبقية المجلدات.
4. اضغط `Commit changes`.
5. من `Settings` ← `Pages` اجعل المصدر: `Deploy from a branch` ← الفرع `main` ← المجلد `/ (root)`.

يستغرق النشر دقيقة أو دقيقتين. لو رأيت نسخة قديمة، أعد التحميل مع تفريغ الذاكرة (Ctrl+Shift+R).

**من سطر الأوامر:**

```bash
git clone https://github.com/khalidreads/khalidreads.github.io.git
cd khalidreads.github.io
# انسخ محتويات مجلد site هنا
git add .
git commit -m "الموقع الجديد"
git push
```

**للمعاينة على جهازك قبل الرفع:**

```bash
cd site
python3 -m http.server 8000
# ثم افتح http://localhost:8000
```

> افتح الموقع عبر خادم محلي كما في الأمر أعلاه، لا بالنقر المزدوج على الملف؛
> بعض المتصفحات تمنع تحميل ملفات JavaScript من مسار `file://`.

## ٣) إضافة تدوينة جديدة

**الطريقة السهلة:** افتح `admin.html` واكتب وانشر — اللوحة تنشئ صفحة التدوينة،
وتحدّث الفهرس و`sitemap.xml`، كل ذلك وحدها (القسم ١٠).

**الطريقة اليدوية،** خطوتان:

1. أنشئ مجلدًا باسم إنجليزي مختصر داخل `posts/` مثل `posts/dostoevsky-idiot/`،
   وانسخ فيه ملف `posts/_template/index.html`، ثم غيّر العنوان والتاريخ والمحتوى
   ورابط `canonical` ووسوم `og:` في أعلاه.
2. افتح `assets/data/posts.js` وأضف سطرًا في **أعلى** المصفوفة:

```js
{
  title:  'عنوان التدوينة',
  date:   '2026-09-01',              // YYYY-MM-DD
  tag:    'قراءة',
  url:    'posts/dostoevsky-idiot/',
  excerpt:'سطر أو سطران يظهران في القائمة.',
  image:  'assets/img/posts/الصورة.webp'   // اختياري: مصغّرة البطاقة
},
```

الحقل `image` يجعل البطاقة تعرض مصغّرة كما في Blogger. لا تشغل بالك به
غالبًا: لوحة الكتابة وأداة الاستيراد تلتقطان **أول صورة في التدوينة**
وتضعانها فيه تلقائيًا؛ وإن حُذفت الصورة لاحقًا اختفت المصغّرة وعادت
البطاقة نصّية بلا كسر.

الترتيب يتم تلقائيًا من الأحدث، وتظهر التدوينة في الواجهة وفي صفحة الأرشيف.

## ٤) حذف تدوينة

**التدوينة شيئان لا شيء واحد**، وهذا أكثر ما يُربك:

| ما هو | أين | ماذا يفعل |
| --- | --- | --- |
| الصفحة | `posts/اسمها/index.html` | ما يراه القارئ حين يفتح الرابط |
| سطرها في الفهرس | `assets/data/posts.js` | ما يجعلها تظهر في قائمة المدونة |

فإن حذفت المجلد وحده بقي السطر يعرض التدوينة في الصفحة الرئيسة، والضغط
عليها يؤدي إلى صفحة ٤٠٤. وإن حذفت السطر وحده اختفت من القائمة وبقيت
صفحتها تعمل لمن يعرف رابطها.

**الطريقة السهلة — من لوحة الكتابة:**

1. اختر التدوينة من قائمة «ماذا تكتب؟».
2. اضغط **«احذف التدوينة»** (يعمل الزر فقط بعد اختيار تدوينة).
3. يسألك سؤالين: تأكيد الحذف، ثم أتحذف صورها أيضًا؟

يحذف الصفحة، وصورها في `assets/img/posts/` التي تبدأ باسمها وحدها،
وسطرها من الفهرس. ولو كنت قد حذفت المجلد يدويًا من قبل، فسيتخطّاه
ويكمل تنظيف الفهرس.

**الطريقة اليدوية** إن أردت:

1. احذف مجلد `posts/اسمها/` من المستودع.
2. افتح `assets/data/posts.js` واحذف الكتلة الخاصة بها كاملة، من `{`
   إلى `},` — انتبه ألّا تترك فاصلة زائدة أو قوسًا مفتوحًا، فخطأ واحد
   يُفرغ قائمة التدوينات كلها.
3. احذف صورها من `assets/img/posts/` إن وُجدت.

> التدوينات المنقولة من Blogger سطرها في `assets/data/posts-blogger.js`
> لا في `posts.js`. اللوحة تعرف الفرق وتحذف من الملف الصحيح، لكن انتبه
> أن إعادة تشغيل `import-blogger.py` تُرجعها من جديد؛ فإن أردت حذفها
> نهائيًا فاحذفها من مدونة Blogger أيضًا أو لا تُعد تشغيل المُحوِّل.

## ٥) تعديلات شائعة

**قائمة التنقّل:** في أعلى `assets/js/site.js` توجد مصفوفة `NAV`.
عدّلها مرة واحدة فتتغيّر في الترويسة والدرج والتذييل معًا.

**البحث:** صندوق في الرئيسية وصفحة الأرشيف، يبحث في العنوان والمقتطف
والتصنيف واسم المؤلف والناشر. البحث في الرئيسية يتخطّى حدّ «آخر ثلاث
تدوينات» فيعرض كل ما يطابق. ومفتاح `Escape` يمسح البحث.

**الناشر:** حقل اختياري في لوحة الكتابة، افتراضيّه «خالد الحمدان»،
يظهر يمين تاريخ التدوينة. اتركه فارغًا فلا يظهر شيء.

**اسم الموقع والختم:** في الدالة نفسها داخل `site.js` (`brand-name` و`brand-tag`
والحرف `خ` داخل `<span class="seal">`).

**الألوان والخطوط:** في أول `assets/css/site.css` داخل `:root`. تغيير `--wine`
مثلًا يغيّر لون الروابط والأزرار والختم والعناوين في كل الصفحات دفعة واحدة.

**بيت الشعر في الواجهة:** في `index.html` داخل `<div class="bayt">` — الصدر
والعجز والسطر الذي تحته.

**إضافة كتاب:** الأسهل ألّا تفعلها يدويًا: أضِف الكتاب في Goodreads كعادتك
ثم شغّل أداة المزامنة (القسم ٨) فتحدّث المكتبة كلها دفعة واحدة. وإن أردت
يدويًا: أضف عنصرًا بنفس الحقول في `assets/data/books.js`. للغلاف: إمّا حقل
`cover` فيه رابط صورة مباشر، وإمّا `tools/fetch-covers.py` (القسم ٧).

## ٦) الخلفية

الخلفية أغصان حبر وأزهار كرز مرسومة بصيغة SVG، موزّعة على الزوايا الأربع
والوسط فارغ. طبّقتُها على شكل أربع طبقات في `site.css` (في `body::after`)
بدل صورة واحدة، حتى تبقى الزينة في زواياها على أي مقاس شاشة: جوال طويل أو
شاشة عريضة جدًا، بلا قصّ يبتلع الرسم.

لو فضّلت صورة واحدة تُمدّ بـ `background-size: cover`، فالملف
`assets/img/bg-blossom.svg` جاهز بمقاس ١٦:٩. استبدل كتلة `body::after`
في `site.css` بهذه:

```css
body::after{
  content:"";
  position:fixed; inset:0; z-index:-1; pointer-events:none;
  background-image:url(../img/bg-blossom.svg);
  background-size:cover;
  background-position:center;
  background-repeat:no-repeat;
}
```

لتفتيح الخلفية أو تغميقها غيّر قيمة `opacity` في القاعدة نفسها.

## ٧) أغلفة الكتب من Goodreads

> مكتبتك الحالية أغلفتها **مدمجة أصلًا**: كل كتاب في `books.js` يحمل حقل
> `cover` برابط غلافه، وأداة المزامنة تحفظه. ما يلي يلزم الكتب الجديدة فقط.

الموقع يجرّب ثلاثة مصادر للغلاف بالترتيب:

1. الرابط المحفوظ في `assets/data/covers.js` (من Goodreads).
2. Open Library بحسب حقل `isbn`.
3. عنوان الكتاب مكتوبًا بخط أميري.

ملف `covers.js` يبدأ فارغًا. لملئه شغّل هذا الأمر **مرة واحدة** على جهازك:

```bash
cd khalidreads-site
python3 tools/fetch-covers.py
```

يفتح السكربت صفحة كل كتاب في Goodreads، ويلتقط رابط الغلاف من وسم `og:image`،
ويحفظه في `covers.js`. ثم ارفع الملف مع بقية الموقع. بعدها لا يتصل الموقع
بـ Goodreads إطلاقًا؛ يقرأ الروابط المحفوظة فحسب.

**لماذا سكربت ولا يفعلها الموقع تلقائيًا؟** لأن المتصفح ممنوع من قراءة صفحات
Goodreads من نطاق آخر (سياسة CORS)، ورابط الصورة لا يمكن اشتقاقه من رقم الكتاب
لأنه يحوي رقمًا عشوائيًا لا نمط له:

```
كتاب رقم 15824998
الغلاف .../books/1344819637i/15824998.jpg
              ↑ هذا الرقم لا يُعرف إلا بفتح الصفحة
```

**ملاحظات:**

- الجولة الكاملة (٣٢٣ كتابًا) تستغرق نحو عشر دقائق، بمهلة ١٫٥ ثانية بين كل طلب
  وآخر حتى لا يحجبك Goodreads.
- جرّب أولًا: `python3 tools/fetch-covers.py --limit 20`
- السكربت يحفظ تقدّمه كل عشرة كتب، فيمكنك إيقافه بـ Ctrl+C ثم تشغيله فيكمل.
- إن ظهرت أخطاء 403 متتالية فقد حجبك Goodreads مؤقتًا؛ انتظر ساعة ثم:
  `python3 tools/fetch-covers.py --delay 4`
- لإعادة محاولة الكتب التي لم يوجد لها غلاف: `--retry`
- لتصحيح غلاف بعينه، حرّر سطره في `covers.js` مباشرة وضع أي رابط صورة.
- ١٦٨ من كتبك بلا ISBN، أي أنها تظهر الآن بعنوان نصّي؛ هذه أكثر من سيستفيد
  من الخطوة.

## ٨) مزامنة المكتبة من Goodreads

Goodreads أغلقت واجهتها البرمجية منذ ٢٠٢٠، فلا مزامنة حية ممكنة. البديل
الرسمي الثابت هو ملف التصدير، والمزامنة به دقيقتان كلما أردت:

1. في Goodreads: `My Books` ← `Import and export` ← `Export Library`،
   فيُنزَّل ملف `goodreads_library_export.csv` فيه مكتبتك كاملة.
2. ثم:

```bash
cd khalidreads-site
python3 tools/sync-goodreads.py goodreads_library_export.csv
```

السكربت يحدّث `books.js` كاملًا: الكتب الجديدة تُضاف، والتقييمات
والمراجعات والتواريخ والرفوف تتحدث، و**إضافاتك اليدوية تبقى** (حقل
`cover` الذي وضعته بنفسك مثلًا يُنقل كما هو، وأغلفة `covers.js` محفوظة
برقم الكتاب فلا تتأثر). الكتاب الموجود عندك وغير الموجود في CSV يُبقى
مع تنبيه؛ أضف `--prune` لحذفه إن كنت حذفته من Goodreads فعلًا.

بعد المزامنة شغّل `tools/fetch-covers.py` لجلب أغلفة الكتب الجديدة فقط.

## ٩) نقل مدونة Blogger إلى الموقع

**الخطوة الأولى — صدّر مدونتك:**
في Blogger افتح `الإعدادات` ← `إدارة المدونة` ← `نسخ احتياطي للمحتوى`.
يُنزَّل ملف باسم مثل `blog-08-10-2026.xml` فيه كل تدويناتك وصورها وتصنيفاتها.

**الخطوة الثانية — شغّل المُحوِّل:**

```bash
cd khalidreads-site
python tools/import-blogger.py blog-08-10-2026.xml
```

جرّب أولًا على خمس تدوينات: `python tools/import-blogger.py blog-08-10-2026.xml --limit 5`

**ما الذي يفعله:**

- يقرأ التدوينات المنشورة فقط، ويتجاهل المسودّات والتعليقات.
- ينظّف تنسيقات Blogger المضمّنة (الألوان والخطوط والأحجام وأزرار
  المشاركة) فيأخذ النص تصميم الموقع، ويبقى الترقيم والاقتباسات والروابط.
- **يُنزّل صور التدوينات** إلى `assets/img/posts/` ويعدّل روابطها، فلا
  يبقى الموقع معتمدًا على خوادم Blogger إن أُغلقت المدونة يومًا.
- يكتب صفحة لكل تدوينة في `posts/` باسم مثل `2026-08-blog-post.html`
- يكتب فهرسها في `assets/data/posts-blogger.js`

**خيارات:**

| الخيار | ما يفعله |
| --- | --- |
| `--limit 5` | حوّل خمس تدوينات فقط (للتجربة) |
| `--keep-image-urls` | لا تُنزّل الصور، أبقِ روابط Blogger |

**بعد النقل:**

- عاين الموقع محليًا وتصفّح التدوينات المنقولة قبل الرفع.
- تصنيفات Blogger («روايات قرأتها»، «كتب قرأتها»، «ترجماتي») تصير
  أزرار تصفية في صفحة `archive.html` تلقائيًا.
- التدوينات التجريبية الثلاث التي جاءت مع الموقع (`hello`،
  `lady-susan`، `oliver-twist`) صارت زائدة غالبًا؛ احذف ملفاتها من
  `posts/` واحذف أسطرها من `assets/data/posts.js`.
- **الصفحات الثابتة** في Blogger (إن وُجدت) لا تُحوَّل تلقائيًا؛
  السكربت يخبرك بعددها، وتنسخ محتواها يدويًا إلى `about.html`.
- إن نشرت لاحقًا في Blogger، صدّر نسخة جديدة وأعد تشغيل المُحوِّل؛
  يعيد توليد كل شيء دون أن يمسّ تدويناتك المكتوبة هنا.

**بعد اكتمال النقل** يمكنك إغلاق مدونة Blogger أو تركها، ووضع تحويل
منها إلى العنوان الجديد.

## ١٠) لوحة الكتابة (النشر بلا كود)

افتح `admin.html` على موقعك: `https://khalidreads.github.io/admin.html`
تكتب فيها كما في Blogger — عنوان، تصنيف، ومحرّر بأزرار للعناوين والاقتباس
والقوائم والروابط والصور — ثم تضغط «انشر»، فتظهر التدوينة على الموقع خلال
دقيقة تقريبًا.

### تجهيزها مرة واحدة

**١) أنشئ رمز وصول في GitHub:**

`Settings` ← `Developer settings` ← `Personal access tokens` ←
`Fine-grained tokens` ← `Generate new token`

- **Repository access:** اختر `Only select repositories` ثم مستودع موقعك وحده.
- **Permissions:** `Repository permissions` ← `Contents` ← **Read and write**.
  لا تعطه أي صلاحية أخرى.
- **Expiration:** اختر مدة تناسبك؛ عند انتهائها أنشئ رمزًا جديدًا والصقه.

انسخ الرمز فور ظهوره، فلن يظهر مرة أخرى.

**٢) في لوحة الكتابة:** افتح «الاتصال بالمستودع»، واكتب اسم المستخدم واسم
المستودع والرمز، ثم اضغط «تحقّق من الاتصال». إن ظهرت نقطة خضراء فأنت جاهز.

### الاستعمال

- **تدوينة جديدة:** اكتب العنوان، ثم النص في المحرر، ثم «انشر».
  اسم الملف والمقتطف يُكتبان تلقائيًا، ويمكنك تغييرهما.
- **تعديل تدوينة قديمة:** اخترها من قائمة «ماذا تكتب؟»، فتُفتح للتعديل،
  ثم انشر لتستبدل القديمة. يعمل هذا مع التدوينات المنقولة من Blogger أيضًا.
- **التنسيق:** كل زر يعمل على **ما تحدّده أنت وحده** لا على السطر كاملًا:
  العريض والمائل واللون والحجم. أما العناوين والمحاذاة والاقتباسات فتخصّ
  الفقرة كلها بطبيعتها.
- **الزر الأيمن:** اضغط بزر الفأرة الأيمن داخل المحرر فتظهر قائمة بأكثر
  الأوامر استعمالًا (عنوان، رابط، لون، اقتباس، بيت شعر، محاذاة).
- **الألوان:** أربعة ألوان من لوحة الموقع، وزر لاختيار أي لون آخر،
  وزر لإزالة اللون من المحدّد.
- **الاقتباسان:** «مميّز» بخلفية وردية، و«بسيط» بخط جانبي فقط. اضغط الزر
  نفسه مرة ثانية ليعود النص فقرة عادية. وتستطيع تلوين النص داخلهما وتكبيره.
- **المصدر ورقم الصفحة:** فور إنشاء الاقتباس تُسأل عن المصدر («ص ٦٦» أو
  «أدب الكُتّاب · ص ١٠٣») فيظهر سطرًا صغيرًا ذهبيًا تحته. ولتعديله لاحقًا
  ضع المؤشر داخل الاقتباس واضغط «المصدر / الصفحة»، ولحذفه اتركه فارغًا.
  الأرقام تُحوَّل تلقائيًا إلى الأرقام العربية.
- **أبيات الشعر:** زر «أبيات شعر» يفتح مربعًا منبثقًا تكتب فيه القصيدة
  كما هي — الصدر في سطر والعجز في السطر الذي يليه، بيتًا بعد بيت — ثم
  «أدرج الأبيات». تظهر متوسطةً الصفحة بأعمدة متحاذية كما في منسّق الشعر،
  وعلى الجوال ينقسم البيت: الصدر سطر والعجز سطر تحته.
- **التقييم والمؤلف والصفحات:** حقول جاهزة أعلى اللوحة؛ تظهر في شريط أنيق
  أعلى التدوينة، وتظهر النجوم كذلك بجانب التدوينة في قائمة المدونة.
- **الصور:** زران: «صورة من الجهاز» يسألك عن **وصفها** ثم يصغّرها إلى
  ١٦٠٠ بكسل بصيغة WebP ويرفعها إلى `assets/img/posts/` ويدرجها بأبعادها
  وتحميل كسول؛ و«صورة برابط» تلصق فيه رابط صورة خارجية مباشرًا. الصور
  المرفوعة تظهر في المحرر **فورًا** (تُعرض من رابط GitHub الخام ريثما
  ينتشر الموقع)، وأول صورة في التدوينة تصير مصغّرة بطاقتها وصورة مشاركتها.
- **المسودّات:** تُحفظ في متصفحك تلقائيًا كل نصف دقيقة، فلا يضيع ما كتبت
  إن أُغلقت الصفحة. وهي محفوظة عندك فقط ولا تُرفع إلى الموقع.

### عن الخصوصية والأمان — بصراحة

GitHub Pages استضافة **ثابتة**: لا خادم فيها ولا قاعدة بيانات، فلا يمكن عمل
تسجيل دخول حقيقي بكلمة سر. ما يحمي موقعك هو **رمز الوصول** لا إخفاء الصفحة:

- الصفحة نفسها لا تفعل شيئًا بلا رمز، فمن يفتحها لا يرى إلا نموذجًا فارغًا.
- الرمز يبقى في متصفحك أنت (أو تكتبه في كل مرة إن ألغيت خيار الحفظ).
- `robots.txt` وسطر `noindex` يمنعان ظهورها في محركات البحث، لكنهما
  **لا يمنعان** من يعرف العنوان من فتحها. هذا إخفاء لا حماية.

**الأكثر أمانًا** إن أردت: لا ترفع `admin.html` إلى GitHub أصلًا. أبقِ نسخة
منها على جهازك وشغّلها محليًا:

```bash
cd khalidreads-site
python -m http.server 8000
# ثم افتح http://localhost:8000/admin.html
```

تنشر منها إلى الموقع كما هي، ولا يراها أحد أبدًا. العيب الوحيد أنك لن
تستطيع النشر من الجوال.

**في كل الأحوال:** لا تفتح اللوحة على جهاز عام، وإن شككت في رمزك احذفه من
GitHub فورًا (زر Revoke) وأنشئ غيره.

> اللوحة ملفان: `admin.html` للشكل و`assets/js/admin.js` للمنطق. ارفعهما
> معًا أو أبقهما معًا على جهازك؛ أحدهما لا يعمل بلا الآخر.

## ١١) كيف تختفي `.html` من الروابط

الخدعة بسيطة، ولا تحتاج إعدادًا ولا خادمًا: **أي خادم ويب يعرض تلقائيًا
ملفًا اسمه `index.html` حين يُطلب المجلد الذي يحويه**. فبدل صفحة اسمها
`about.html` نصنع مجلدًا `about/` ونضع الصفحة بداخله باسم `index.html`:

```
about.html               →  /about.html      ✗
about/index.html         →  /about/          ✓
```

وهذا ما فعلته بكل صفحات الموقع. القاعدة في ثلاث نقاط:

1. **اسم المجلد هو الرابط.** `timeline/ladysusantimeline/index.html`
   يصير `/timeline/ladysusantimeline/` — تمامًا كما أردت.
2. **الملف بداخله يجب أن يُسمّى `index.html`** بالضبط، بحروف صغيرة.
3. **صحّح مسارات الأصول.** كل مجلد تنزل به مستوًى يحتاج `../` إضافية.
   صفحة في `posts/x/` تبعد مستويين عن الجذر، فمسارها
   `../../assets/css/site.css`، وخاصية `data-root="../../"`.
   نسيان هذه الخطوة أشهر سبب لصفحة تظهر بلا تنسيق.

**الاستثناء الوحيد: `404.html`** يبقى في الجذر بهذا الاسم، فهذا ما يبحث عنه
GitHub عند رابط خاطئ.

**لإضافة خط زمني جديد:** أنشئ `timeline/اسم-جديد/index.html` بعمق مستويين،
ثم أضف بطاقته في `timeline/index.html`.

**والروابط القديمة؟** لو كان أحد قد حفظ `/posts/hello.html` فسيصله خطأ ٤٠٤.
إن أهمّك ذلك ضع ملفًا قديم الاسم فيه سطر تحويل واحد:

```html
<meta http-equiv="refresh" content="0; url=/posts/hello/">
```

## ١٢) SEO والمشاركة

كل صفحة فيها `canonical` ووسوم Open Graph وبطاقة Twitter، فتظهر الروابط
عند مشاركتها ببطاقة فيها العنوان والوصف وصورة `assets/img/og-cover.png`
(وإن كان في التدوينة صورة، صارت هي صورة البطاقة).

`sitemap.xml` **تحدّثه لوحة الكتابة تلقائيًا** مع كل نشر وحذف، فلا
تحرّره يدويًا. من كتب تدوينة يدويًا فليضف رابطها فيه بنفس نمط الأسطر
الموجودة.

> **مهم:** الروابط المطلقة في الموقع مكتوبة على أساس
> `https://khalidreads.github.io/`. إن كان اسم مستخدمك في GitHub مختلفًا،
> فاستبدل هذا النطاق بنطاقك في كل الملفات (بحث واستبدال شامل مرة واحدة)،
> أما لوحة الكتابة فتستنتج النطاق من اسم المستخدم وحدها بلا تعديل.

الصور التي ترفعها اللوحة تُدرَج بصيغة WebP (أو JPEG على المتصفحات الأقدم)
مع سؤالك عن **وصف الصورة** وإدراج أبعادها و`loading="lazy"` — فلا تقفز
الصفحة أثناء التحميل ولا تُحمَّل صور خارج الشاشة.

## ١٣) التعليقات

التعليقات تعمل عبر **giscus**: تُخزَّن في GitHub Discussions داخل مستودعك،
مجانًا وبلا إعلانات ولا خادم، وتحذف وتدير من GitHub مباشرة. خانة التعليقات
موجودة أسفل كل تدوينة لكنها **مخفية حتى تفعّلها**:

1. فعّل Discussions في المستودع: `Settings` ← `General` ← `Features` ← ✅ Discussions.
2. ثبّت تطبيق giscus على المستودع من: https://github.com/apps/giscus
3. في تبويب Discussions أنشئ تصنيفًا باسم «التعليقات» ونوعه **Announcement**
   (حتى لا يستطيع أحد فتح نقاشات جديدة بنفسه؛ giscus وحده ينشئها).
4. افتح https://giscus.app واختر مستودعك، والربط **pathname**، والتصنيف «التعليقات».
5. انسخ القيم الأربع من الكود الذي يظهر (`data-repo` و`data-repo-id`
   و`data-category` و`data-category-id`) وألصقها في أعلى
   `assets/js/comments.js`، ثم ارفع الملف. انتهى.

**فرق مهم عن Blogger:** المعلّق يحتاج حساب GitHub (تسجيل دخول واحد بزر).
إن كان جمهورك بعيدًا عن GitHub وأردت تعليقات الزوار بلا حساب، فالبديل
المعروف Disqus — لكنه يعرض إعلانات في خطته المجانية ويتتبع القراء ويثقل
الصفحة، ولهذا لم أعتمده.
